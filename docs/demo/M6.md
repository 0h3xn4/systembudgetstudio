# M6 Polish — demo note

```
budget export-examples demo
budget compare demo/cubesat_3u_eps demo/cubesat_3u --out out      # two revisions/projects, differences highlighted
budget compare demo/cubesat_3u_eps --scenario-a one_day --scenario-b other --out out
budget guide --out guide                                          # offline HTML + PDF
system-budget-studio                                              # File > New project (guided), Help > User guide, tab Compare
```

**Comparison.** The GUI tab *Compare* (side A: the open project, side B: another folder or another scenario) lists every value that differs, per budget, with the change, the change in percent and a coloured status (changed, added, removed, now computed, now n/a). Export writes `compare.xlsx/.pdf/.docx/.json` and `compare_differences.csv`. Values are compared as displayed; more than 200 differences per budget are counted and stated.

**Guided mode.** File > New project: name and folder, sample spacecraft, orbit (altitude, inclination, RAAN), scenario length, review, Finish. The project is created, opened, and its first power timeline computed. The automated test walks the wizard and has the first budget on screen in a few seconds (the limit in the test is the spec's ten minutes, with a two-minute guard for slow CI runners).

**User guide.** 12 chapters in `budget_core/guide/chapters/`, rendered inside the window (Help > User guide, F1) and as one self-contained HTML file and a PDF. The last chapter, *Equations and sources*, is generated: every equation with its source or `SOURCE_MISSING`, the shipped constants with sources, and, with a project open (or `--project`), every sourced number of that project with its placeholder status.

**Installers.** The bundle has `system-budget-studio` and `budget`. Linux: `./install.sh` (per user, no admin, manifest-based `uninstall.sh`). Windows: Inno Setup per-user installer and a portable zip. The Installers workflow builds on Rocky Linux 8 and Windows, installs as an ordinary user and uninstalls on every change to `packaging/`. Verified locally here: the Linux bundle builds, passes `--self-test` (GUI and CLI executables), installs into a fresh HOME, runs `budget compare`, and uninstalls leaving nothing behind. **Not verifiable here:** the Windows installer and the Rocky 8 container run (only CI can); see `docs/INSTALL_CHECKLIST.md`.

**Licences.** `python packaging/licence_check.py` finds only permissive and LGPL runtime licences (PySide6 under LGPL-3.0); `docs/LICENCES.md` lists them; a test keeps the list current.

**Performance.** One week at 1 s with 200 units: environment about 4.3 s, power 0.2 s, `budget power-timeline` about 8 s end to end. DOCX export of large tables is twice as fast (4.9 s to 2.4 s for the 200-unit power report).

**Acceptance.** Golden XLSX and PDF for thermal, timeline and link passes of all three reference projects (16 new golden files), plus the existing power, mass, thermal, link and comparison goldens; wizard timed test; clean-machine checklist (owner sign-off).

Open for the owner: everything listed after M5 (equations `SOURCE_MISSING`, real numeric inputs, D-043, D-048, D-054, D-059, D-064, DV-L2, SpaceMissionStudio samples, repository privacy, branch protection) and, new: the Windows installer and RHEL 8 results from the first CI run, a sun-synchronous helper for the wizard (needs J2 and a source), and the clean-machine sign-off.
